# TRADE MONITOR

タブレット（横画面）で、登録した銘柄（日本株・米国株）のチャートを自動で切り替えながら表示する Web アプリです。GitHub Pages で公開でき、ビルドは不要です。

- 公開 URL：https://take3431.github.io/trade-monitor/
- 想定端末：Android タブレット（Chrome）。iPad（Safari）でも動作します。

## 入口のパスワード
- サイトを開くと、最初にパスワードを聞きます。正しく入力するまで、アプリ本体を読み込まず、株価の取得先にも一切通信しません（リンクを開いただけの人が通信を発生させないため）。
- 一度通った端末は覚えておき、次回からは聞きません。パスワードを変えると、すべての端末で聞き直します。
- 全角・小文字で入力しても通ります。
- 5回間違えると5分、10回で30分、15回以上は1回ごとに1時間、入力できなくなります。
- 個人情報を守るためではなく、知らない人による通信を防ぐための簡易的な鍵です。パスワード自体は置かず、照合用の値（SHA-256）だけを `js/gate.js` に置いています。変えるときは、新しいパスワード（半角大文字）の SHA-256 をこの値と差し替えます。

## 画面と機能

### メイン画面
- 上部：市場の状態（例：「東証・接続中（後場）」）、次の切り替えまでの「残り N秒」、一時停止/再生、前/次、全画面ボタン、設定（≡）。
- 銘柄ヘッダー：コード・銘柄名・現在値・前日比・騰落率。右側に「巡回の位置（例 2 / 6）」と「データの時刻」。銘柄名が長いときは、銘柄名の文字だけ自動で小さくします。銘柄名をタップすると、Yahoo!ファイナンス（日本）のその銘柄のページを新しいタブで開きます。
- チャート：左右2枚。足種は 5分足・日足・週足・月足 から選べます（既定は左が日足、右が月足）。
  テクニカル指標は移動平均線（日足 5/25、週足 13/26、月足 12/24）、ボリンジャーバンド（20, 2σ）、出来高です。
- 騰落の色は既定が日本式（上昇＝赤）で、設定で米国式（上昇＝緑）にできます。
- 「東証・接続中」の部分をタップすると「通信状況」画面が開きます（通信回数、保存データの量、データの取得間隔や上限などの決まり、最近の通信履歴）。

### 自動切替と操作
- 切り替え間隔は 20/30/60/90 秒、またはカスタム（10〜300秒）です。
- チャートに触れると、最後の操作から10秒間は自動切替を止めます。
- 自動切替・データ更新のたびに、拡大・縮小・スクロールは初期状態に戻します。ある銘柄の操作は他の銘柄に影響しません（操作中の10秒間は保持）。
- 設定で「市場時間外の自動切替」を停止にもできます。
- キーボード：← / → で前/次、Space で一時停止/再生。

### 設定画面
- 左：登録銘柄一覧（最大999銘柄）。表示対象の ON/OFF、削除、銘柄名タップで表示名の変更、左端の ⋮⋮ のドラッグで並び替え（並び順はその場で保存）。
- 右：自動切替、チャート、表示（ダークモード・騰落カラー・文字サイズ・画面スリープ防止）の設定。
- 右側の設定（自動切替・チャート・表示と動作）は、「設定を保存して戻る」を押したときだけ反映されます。右上の × で戻ると、右側の変更は捨てます。
- 銘柄の登録・削除・並び替え・表示対象・表示名・アラートはその場で保存されるので、× で戻るだけで反映されます（「設定を保存して戻る」ボタンは出ません）。
- 確認や入力の画面はアプリ内に表示します（ブラウザ標準の確認画面は Android で全画面を解除してしまうため使いません）。

### 全銘柄一覧
- 設定画面の「全銘柄一覧」で、登録した全銘柄を「現在値・前日比」のタイルで並べます。値上がりは赤、値下がりは緑（騰落カラーの設定に従う）で、色の濃さは前日比の大きさ（5%で最大）です。
- 上部に値上がり・値下がり・変わらずの銘柄数を出し、「登録順・値上がり順・値下がり順」で並べ替えられます。
- タイルを押すと、その銘柄のチャートを表示します。アラート中の銘柄にはベル、表示対象が OFF の銘柄には「表示OFF」を付けます。
- 保存済みのデータを並べるだけで、この画面のための通信はしません（開いている間に届いた株価はその場で反映）。

### アラート
- 設定画面の「アラート設定」で、一覧が「現在値・設定株価・アラート」の表示に切り替わり、右側にアラート通知設定が出ます。
- アラートを ON にすると設定株価を入力できます（OFF の間は入力できません）。全角・半角の混在や「9,000」「９０００円」のような書き方も読み取り、表示は半角にそろえます。
- 設定株価の横の ▲ は「今より上（上抜けで通知）」、▼ は「今より下（下抜けで通知）」の意味です。
- 行の右端の消しゴムで、設定株価を消してアラートを OFF にします（銘柄は消えません）。
- 現在値が設定株価をまたいだ瞬間（上抜け・下抜け）に通知し、その銘柄のアラートは自動で OFF に戻ります（設定株価の付近で上下しても何度も鳴らないように）。
- 通知は画面内のカード（株価画面では右上、設定画面では左下）と通知音（アプリ内で作る「ピンポーン」。音声ファイルは読み込みません）で知らせます。どちらも ON/OFF できます。
- 通知音は「鳴らす時間」（5〜60秒、既定10秒）のあいだ鳴り続け、通知カードを消すと止まります（ポップアップが OFF のときは、画面に触れると止まります）。
- 通知カードは × を押すか横にスライドするまで消えません。カードのほかの部分を押しても何も起きません。ページを読み込み直しても残ります。
- 判定には、いつもの表示・先読み・まとめて取得で届いた株価を使います。アラートのための通信はしません。そのため、表示対象が OFF の銘柄は判定されません。
- 音は、ページを開いてから一度画面に触れたあとでないと鳴りません（ブラウザの決まり）。アラート音を使っている間は、12時間ごとの自動読み込み直しをしません。

### 銘柄の登録と検索
- 主要な指数・為替なども登録できます：日経平均株価・日経500、S&P500・NYダウ・ナスダック総合・ナスダック100・SOX指数・ラッセル2000・VIX指数・米国10年国債利回り、香港ハンセン・上海総合・KOSPI・台湾加権・インドSENSEX・英FTSE100・独DAX・ユーロストックス50、米ドル/円・ユーロ/円、ビットコイン、金先物、WTI原油先物。「日経平均」「ダウ」「ドル円」などで検索すると一番上に出ます。
- TOPIX は指数そのものを Yahoo から取得できないため、「TOPIX」で検索すると連動ETF（1306 NEXT FUNDS TOPIX連動型上場投信）が一番上に出ます。
- 日本株は4桁のコード（例 `7203`, `130A`）、米国株はティッカー（例 `AAPL`, `BRK-B`）で登録します。
- 銘柄名でも検索でき、ひらがな・カタカナ・英語のどれでも探せます。長音「ー」の有無や、英字の読み（「じぇいぴーもるがん」→ JPモルガン）にも対応しています。同じ一致度なら規模の大きい会社が上に来ます。
- 日本株：`data/jp-stocks.json`（JPX 公表の東証上場銘柄一覧。2026年10月末時点で4,444銘柄、読みがな・規模区分つき）。
- 日本株の通称・略称・ブランド名・旧社名（NEC→日本電気、ホンダ、ユニクロ、JR東日本、ドンキ、au、ヤフー、新日鉄 など約280銘柄）でも探せます。一覧は `tools/jp_aliases.py` にあり、追加すると次に銘柄一覧を作り直したときにも引き継がれます。
- 米国株：`js/us-names.js`（約1,160銘柄の日本語名）。S&P500・ナスダック100の主要銘柄、時価総額100億ドル以上の米国上場銘柄（アンソロピック・スペースXなどの新規上場や、外国企業の ADR を含む）、注目の成長株（AI・量子・宇宙・暗号資産・原子力など）、人気の ETF を収録しています。同じ一致度なら時価総額の大きい会社を上に出します。辞書に無いものは、英字で入力すると Yahoo の検索結果（英語名）から探します。
- 米国株の一覧は、Yahoo Finance の時価総額順の一覧をもとに作っています（2026年11月時点）。新しく上場した大型株が出てこないときは、一覧を作り直します。
- 登録した銘柄はすぐにデータを取得します。以前登録していてデータが残っている銘柄は、足りない直近分だけを取得します。

### 全画面
- 右上の ⛶ ボタンで全画面にでき、もう一度押すと戻ります。
- 全画面で使っていた場合は、次に開いたとき、最初に画面に触れた時点で全画面に戻ります（ブラウザの決まりで、触れる前に自動で全画面にはできないため）。
- iPad でホーム画面に追加して使う場合は、Safari と保存場所が分かれるので、設定画面の「銘柄と設定をコピー」「貼り付けて復元」で引き継げます（iPad/iPhone のときだけ表示）。

## データの取得

### 取得元と経路
- 株価データは Yahoo Finance から取得します。ブラウザから直接は呼び出せない（CORS 制限）ため、中継サービス `r.jina.ai` を通します。予備として allorigins・codetabs も持っていて、成功率の高い経路から順に使います。
- 主な経路が6秒以内に応答せず、かつ予備の経路が最近うまくいっている場合だけ、予備にも並行して送ります。失敗した経路はしばらく休ませます。Yahoo の窓口（query1 / query2）は交互に使います。
- 東証のデータは約20分遅れ、米国株はほぼリアルタイムです。
- TradingView 社のチャート描画ライブラリ（Lightweight Charts）はアプリに同梱しています。TradingView のサーバーには一切アクセスしません。

### 取得のしかた
| 場面 | 取得するもの | 通信 |
|---|---|---|
| 初めて表示する銘柄 | 日足10年分。週足・月足はアプリ内で集計 | 1回だけ |
| 場中の更新 | この先表示される最大20銘柄をまとめて（現在値・当日の高値/安値・出来高・直近5日の終値） | 2分に1回まで |
| その日初めて表示する銘柄 | 当日の始値を含む直近5日分（まとめて取得では始値が取れないため） | 1銘柄1日1回 |
| 4日以上更新が空いた銘柄 | 抜けている分（直近1か月分） | 1回 |
| 株式分割・併合を検知した銘柄 | 日足10年分を取り直し | 1回 |
| 約半年ごと（銘柄ごとに150〜209日でずらす） | 日足10年分を取り直し（念のための整合性確保） | 1銘柄1回 |
| 5分足を表示する場合 | 直近5日分の5分足（まとめて取得できない） | 1銘柄5分に1回まで |

- 表示対象が50銘柄を超えると、当日の始値を「最初の1分の値」で近似し（この先表示する最大20銘柄の分をまとめて1回で取得）、その日初めての個別取得も省きます。画面上部に「始値は近似」と小さく表示します。近似になるのは当日の始値だけで、高値・安値・終値・出来高は正確です。
- 保存済みのデータは古くても先に表示し、最新のデータが届いたら入れ替えます。通信に失敗しても画面は空になりません。
- 取得した値が前回と同じなら、保存データの書き換えとチャートの描き直しをしません。

### 株式分割・併合への対応
Yahoo の過去の株価は、分割・併合があると分割後の基準に書き換わります。保存済みの過去分は古い基準のままなので、そのまま継ぎ足すとチャートに段差ができます。
そこで、まとめて取得・個別取得のたびに届く「確定済みの過去の終値」を保存済みの値と同じ日で比べ、3%以上食い違う日があれば分割・併合と判断し、その銘柄だけ10年分を取り直します。検知に追加の通信は不要で、取り直しの1回だけで済みます。
- 保存済みの最後の1本は比べません（場中の値のまま残っていることがあり、値動きの大きい日に誤って分割と判断しないため）。
- 同じ銘柄の取り直しは1日1回までです（Yahoo 側のデータが一時的に食い違っても、通信を使い続けないため）。

### 取得するタイミング
- 東証：データが実際に動く時間帯（約20分遅れのため 9:20〜11:50・12:50〜15:50）だけ取得します。
- 米国：米国東部時間 9:30〜16:00（夏時間は端末の時刻機能で自動判定。日本時間では冬 23:30〜翌6:00、夏 22:30〜翌5:00）。祝日と短縮取引日（13:00 終了）にも対応しています。
- 閉場中・昼休み・休日は、引け後のデータを取得済みなら通信しません。終値の確定を待つため、東証は引けの25分後（15:55）以降、米国は引けの15分後以降に取得したデータを「引け後のデータ」とみなします。
- 休場日は `js/holidays.js`（2025〜2040年、`python3 tools/gen-holidays.py` で生成）。将来分は祝日法・取引所の規則から計算した予定日です。

## 通信回数の上限（アクセス制限を受けないための対策）
- **1日300回まで**（日本時間0時区切り）。銘柄検索も含みます。裏での取得は240回までとし、表示用に60回を残します。上限に達したら翌日0時まで保存済みのデータで表示し、画面上部に「本日の通信上限」と表示します。
- **10年分の取り込み（初回・分割併合の反映・定期の取り直し）は別枠で1日150回まで**。
- **新規登録は1日100銘柄まで**（日本時間0時区切り）。登録した銘柄は10年分を1回取り込むので、一度に大量の通信が起きないようにしています。
- 裏での取り込みは**15秒に1件**（1分に4回まで）。100銘柄なら約25分でそろいます。
- 取り込み枠を使い切った日は、定期の取り直しは直近分の継ぎ足しで代用し（取り直しは翌日以降）、まだデータの無い銘柄は自動切替で飛ばします（「データ未取得」の画面を出さない）。
- 「銘柄と設定をコピー／貼り付けて復元」で一度にたくさんの銘柄を読み込んだ場合も、取り込みは1日150銘柄ずつ進みます。
- まとめて取得に含めるのは、取引時間中は「2分以内に表示する銘柄」（切り替え30秒なら5銘柄）だけ。それより先の銘柄は表示するころには古くなって取り直すことになるため、含めても無駄になります。時間外は値が変わらないので20銘柄まとめて取ります。
- 同時に通信するのは2本まで、開始間隔は1.5秒以上、1分あたり12回まで（裏での取得は4回まで）。
- 「回数制限」の応答を受けたら、その経路を90秒、全体を15秒止めます。
- 失敗が続く銘柄は、2分・4分・8分…と間隔を空けて再試行します（最長30分）。
- 前/次ボタンを連打しても、通信は表示が落ち着いてから（0.35秒後）にまとめます。
- 同じ検索語は10分間検索し直しません。
- **1日の通信量は約3.5MB（上限4MB）に収まるよう、表示対象の銘柄数と切り替え間隔から自動で調整します**（通信状況画面の「決まり」に今の設定と見積もりを表示）。
  - 200銘柄までは今までどおり：取引時間中は2分ごとに最新化、当日の始値は正確（50銘柄まで）または最初の1分の値。
  - 200銘柄を超えると段階的に粗くします：

    | 表示対象 | 取引時間中の更新 | 当日の始値（通信量が多いときは右へ） | 10年分の定期の取り直し |
    |---|---|---|---|
    | 〜50 | 2分ごと | 正確 | 約半年 |
    | 51〜200 | 2分ごと | 最初の1分 → 5分 → 15分の値 | 約半年 |
    | 201〜400 | 3分ごと | 最初の5分 → 15分の値 → 前日終値で代用 | 約1年 |
    | 401〜700 | 4分ごと | 最初の15分の値 → 前日終値で代用 | 約1年 |
    | 701〜999 | 5分ごと | 最初の15分の値 → 前日終値で代用 | 約1年 |

  - それでも4MBを超えるとき（999銘柄を10秒で切り替える場合など）だけ、取引時間中の更新間隔を延ばします。
  - 切り替え間隔は10〜300秒（10秒未満を入れても10秒になります）。切り替えが速くても、通信は上の決まりの範囲でしか行いません。

## データの保存場所と容量の管理
| 保存先 | 内容 | 大きさの目安 |
|---|---|---|
| IndexedDB（端末内） | 銘柄ごとのチャートデータ（日足約2年分、週足・月足は10年分を集計済み）と、その目次 | 1銘柄 数十KB |
| localStorage（端末内） | 銘柄リスト・設定・通信回数 | 数KB |
| メモリ | 最近使った最大60銘柄分。検索結果などの一時データも上限つき | — |

- 保存データは端末の中だけにあり、どこにも送信しません。中身は公開されている株価と、登録した銘柄リストだけです。
- 自動の掃除（起動時と1日1回）：登録から外して30日たった銘柄、3日以上更新していない5分足、旧版の形式のデータを削除します。
- いっぱいになったとき：登録から外した銘柄をすぐ削除し、それでも足りなければ古いものから削除して保存し直します。保存できなくても、メモリ上のデータで表示は続きます。
- ブラウザに保存データを自動で消されにくくする設定（`navigator.storage.persist`）を使っています。

## 長時間の運用
- 保存領域の読み書きは3秒、1件の通信処理は60秒で打ち切り、1か所が止まっても全体が止まらないようにしています。
- 見守り処理（5秒ごと）：表示が止まった・チャートが消えた場合は自動で描き直します。起動から12時間以上たち、市場が閉まっていて操作もしていないときは、ページを読み込み直してメモリを整理します。
- 新しい版の自動読み込み：15分に1回 `version.json` を確認し、新しい版があれば読み込み直します（同じ版では30分に1回まで）。

## 安全対策
- 読み込めるファイルはこのサイトのものだけ、通信できるのは株価の中継先とこのサイトだけに制限しています（Content-Security-Policy）。
- 外部への通信に、このページの URL（参照元）を付けません。
- 表示名などの文字は HTML として解釈しないので、細工された名前を貼り付けても、スクリプトとして実行されることはありません。
- 保存データや「貼り付けて復元」で読み込んだデータは、決められた項目・形式だけを取り出して使います。壊れたデータや想定外の値が混じっていても、不具合の原因になりません。
- 中継サービスに伝わるのは「どの銘柄のデータを求めたか」だけです。銘柄リストや個人を特定する情報は送りません。

```
index.html                 画面
css/style.css              スタイル（ダーク/ライト、文字サイズ）
js/gate.js                 入口のパスワード（通るまでアプリ本体を読み込まない）
js/alerts.js               アラートの通知カード・通知音・設定株価の読み取り
js/app.js                  画面制御・自動切替・設定画面・通信状況・見守り
js/data.js                 データ取得（中継経路・まとめて取得・上限・分割検知）、保存（IndexedDB）と掃除
js/chart.js                チャート描画（Lightweight Charts）・2層表示
js/market.js               東証・米国の取引時間の判定
js/holidays.js             休場日・短縮取引日（自動生成）
js/names.js                銘柄検索（索引・読み・ランキング）
js/us-names.js             米国株の日本語名
data/jp-stocks.json        東証上場銘柄一覧（自動生成）
vendor/                    TradingView Lightweight Charts v4.2.3（Apache-2.0）
tools/update-jp-stocks.py  東証銘柄一覧の更新（JPX から取得、読みがな・規模区分を付与）
tools/jp_aliases.py        日本株の通称・略称（検索用。update-jp-stocks.py が使う）
tools/gen-holidays.py      休場日の生成
tools/bump-version.py      公開前の版番号の付け直し
proxy/cloudflare-worker.js 専用中継（使う場合のサンプル。現在は未使用）
sw.js                      旧版で登録した Service Worker を解除するためだけのファイル
version.json               公開中の版番号
```

## 保守の手順
- **公開するとき**：`python3 tools/bump-version.py` を実行してから push します。読み込むファイルに版番号が付くので、端末に古い版が残りません。
- **東証の銘柄一覧の更新（月1回程度）**：`pip install openpyxl pykakasi` のあと `python3 tools/update-jp-stocks.py`。
- **休場日の更新**：`python3 tools/gen-holidays.py [最終年]`。
- **動作確認**：URL の末尾に `?demo` を付けて開くと、通信せずにダミーデータで表示します。

## 公開手順（初回）
1. このフォルダの中身をリポジトリのルートに置いて push します。
2. GitHub のリポジトリで **Settings → Pages → Build and deployment** を開き、Source に「Deploy from a branch」、Branch に `main` / `/ (root)` を選びます。
3. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で開けます。
